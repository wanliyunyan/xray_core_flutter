# Xray v26.11.9 Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Align the Dart config models, validation, example, and release metadata with the local Xray Core `v26.11.9` checkout while preserving supported legacy input.

**Architecture:** Keep wire-format changes in the existing handwritten model converters, add version-specific validation beside the existing validation modules, and regenerate Freezed output from source. Treat Geodata URL migration and uTLS fingerprint changes as Core runtime behavior, documenting them without duplicating them in Dart.

**Tech Stack:** Dart 3.9+, Flutter, Freezed 4, `flutter_test`, local `../Xray-core/infra/conf` parity checker.

**Spec:** Chat-approved scope from 2026-11-10; no separate design document.

## Global Constraints

- Read Xray Core only from `../Xray-core`; do not modify it.
- Target local Xray Core `v26.11.9` at commit `676eaf66`.
- Preserve legacy Freedom `blockDelay` and root log `loglevel` input compatibility.
- Emit canonical Xray v26.11.9 JSON keys: `delay`, `logLevel`, and root `log.logLevel`.
- Preserve TUN WFP input spelling and duplicates; validation must only determine whether Core accepts the syntax.
- Do not model Geodata `.dat.gz` URL migration or uTLS fingerprints as Dart configuration fields.
- Bump the package version from `0.12.0` to `0.13.0` without changing dependencies.

## Review Focus

- When both root log keys exist, canonical `logLevel` must win over legacy `loglevel`.
- Freedom `delay` or `logLevel` on non-block rules must report exact indexed validation paths.
- Freedom `blockDelay` must still round-trip for old callers while canonical `delay` remains independent.
- TUN CIDR prefixes must accept canonical IPv4 and bracketed IPv6 forms but reject host:port and mapped-IPv6 prefixes exactly as Core does.
- TUN rules that include port 53, `all`, or `allexceptlan` remain syntax-valid in Dart; target-platform DNS/routing prerequisites stay deferred to Core.
